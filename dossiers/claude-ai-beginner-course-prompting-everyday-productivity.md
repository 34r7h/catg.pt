## Section 1. Positioning and setup (lesson 1)

- **Claude AI as assistant (lesson 1):** for people drowning in email/messages who think "I need an assistant" — Claude "will work in your behalf"; it can **automate your work** by connecting **connectors**: Gmail, Google Drive, and your system's files, so tasks like replying to or downloading emails happen inside the assistant.
- **Setup (lesson 1 description):** create an account and install the **desktop application** "to streamline your workflow".
- **Free vs paid (lesson 1):** the course will demo with free and paid tiers; some features "available in the paid tool", and the course claims "you will be able to do a lot of work" on the free plan. Gmail automation is stated as "absolutely available in free plan" (lesson 3).

## Section 2. Interface: Chat, Cowork, Code (lesson 2)

- **Three modules (lesson 2 description):** the Claude dashboard is split into **Chat**, **Cowork** and **Code** — the course teaches the differences between them.
- **Navigation (lesson 2):** modules are switchable with **Ctrl+1/2/3**; settings open via **File → Settings** or **Ctrl+,** (control-comma) in the desktop app.
- **Free vs Pro (lesson 2):** the instructor demonstrates on a **Pro plan**; **Cowork is a Pro feature** ("a lot of people will say that the co-work is not in our account — so this is a pro plan"). The lesson shows "some free features, some pro features, which are very amazing" — the comparison is the point of the lesson.

## Section 3. Connectors and the permission model (lesson 3)

- **Where:** desktop app → **Browse connectors** → pick from Google Drive, Gmail, Google Calendar, Figma, Notion, Zapier ("JAPR" in ASR), Canva, Gamma and others.
- **Connect flow:** click the connector → browser pop-up → log in → **grant access** → back in the desktop app the connector shows as connected → **Configure** button.
- **Permissions are per-connector and granular.** Gmail: default to **read-only**; you can widen it to write/delete, or keep actions gated so Claude must ask ("every time I ask you to write an email, you ask me to approve it"). Google Drive scopes shown: *download file content, get file metadata, get file permission, list recent files, read file content, search file* — plus optional write/delete.
- **Approval-before-action is the course's core safety pattern:** every consequential step (sending, unsubscribing, deleting) comes back as a confirmation the human must allow or deny.

## Section 4. Gmail automation (lessons 3–4)

- **Prompt 1 — inbox optimization:** "give me a summary of the entire inbox… visual and checklist format", scoped to "the last 7 / 15 / 20 days". Claude reads every email (takes minutes), then builds an **interactive dashboard**: e.g. 50 job-alert emails, Glassdoor digest, 10 promo/marketing emails — what fills the inbox and in what volume.
- **Cleanup checklist output:** unsubscribe from daily job alerts, create labels (e.g. finance label for HDFC and Razorpay, job-hunt label), review security alerts, unsubscribe from Fiverr marketing, mute/filter Instagram notifications, label strategy suggestions. The course frames this as a plan Claude hands you — you still perform/confirm the actions.
- **Browser actions (lesson 3):** executing the plan requires the **Claude Chrome extension**; browser actions hit permission prompts ("New permission required — Always allow actions on this site"). The demo drives the Gmail UI: opens the inbox, searches the sender, opens the email, clicks unsubscribe, and **asks the user to confirm** each destructive step. Claude acts via **Claude MCP (Model Context Protocol)** + the extension.
- **Prompt 2 — catch-up summary:** "**Summarize last 15 days emails. Include important emails, action items, deadlines and follow-up required.**" → ~40 emails triaged: critical security alerts, a Microsoft certification renewal with deadline, newsletters, follow-ups flagged ("you need to open one email in the inbox — it gives you a summary, quickly").
- **Prompt 3 — attachment harvesting:** "**Find all the emails with attachment from the last seven days. Download the attachments and organize them into folders** [devices / reports / invoices, others as fallback]. **Create folders if they don't exist.**" → Claude finds 3 emails with attachments, builds a folder structure under Downloads, uses the Gmail API in the browser, downloads each file and sorts it.
- **Prompt 4 — reply drafting (lesson 4):** "**Read the latest email from the inbox and draft a professional reply. Keep it polite and clear. If it's request, respond appropriately. If it's meeting, confirm availability. And show me the draft before sending.**" → Claude triages (Google security alert = automated, no reply needed), picks the most recent non-automated email worth answering (e.g. an Anthropic payment-update request), drafts the reply with subject/key points, and **shows the draft; you click send**. Course claim: "time saving."

## Section 5. Prompt engineering in practice (lessons 4–5)

- **Structured, stepwise prompts win:** the working prompts in the course are lists — step 1 read the file, step 2 do X, step 3 output format — plus explicit constraints.
- **Guardrails the course teaches to always include:** *keep the original file extension*; *if two files share a timestamp, append _1/_2*; *do not overwrite existing files*; *show a preview of changes before applying them*; *wait for my confirmation before the bulk step*.
- **Sample-then-confirm (lesson 5):** for batch generation, "before generating all invoices, only one sample invoice is generated… show me the sample… do not generate all… wait for my confirmation, and then proceed when I give confirmation." This is the course's template for any risky bulk operation.
- **Meta-prompting (lesson 4):** you don't have to write the perfect prompt yourself — describe your requirement simply (dictation in your own language is fine; the instructor notes you can speak Hindi and get English output) and ask an AI ("use the chat… write a best prompt for me to get work done") to **draft a structured prompt back**, then review and adjust it. Course claim: this method produces "a proper prompt" you didn't have to write point-by-point.
- **Chat hygiene / token budget (lesson 5):** usage is metered (session % and weekly limits; demo shows 23% used, resetting after ~3 hours / weekly); "**start a new chat every time**" for a new task so the old context isn't re-scanned and re-charged. Refresh before running a folder task; use **New Task** in Cowork for isolated runs.
- **Observability:** longer tasks show a **task progress** panel (expandable file-by-file log) — the course has you watch each step (read file → load company details → generate).

## Section 6. Google Drive and local file workflows (lessons 4–5)

- **Drive scan report:** "**Scan my Google Drive folder. Analyze all the files and folder and give me a summary** — total number of files, file type distribution, recently added files — and present it clear in a report format." → e.g. 17 items: 3 files, 4 folders, videos, etc.
- **Gmail → Drive bridge:** "**Take last email which has attachment, upload them to Google Drive, rename file using date and time**" → Claude base64-encodes the PDFs, uploads them in parallel, names them by date/time.
- **Organize by extension (Cowork):** start a Cowork chat → "working project" dropdown → **Choose a different folder** → paste prompt: "**organize all files in the given folder… separate folders for each file type by extension and move each file to the corresponding folder**" → demo result: **65 files organized into 16 category folders** (Excel 8, PDFs, images, Python…), watched side-by-side against the open folder.
- **Consolidate (the reverse task):** "**Perform the reverse action of the previous task. In the given location there are multiple folders containing files. Collect all the files from these folders and move them into the single destination folder.**" → Claude asks permission ("allow Claude to permanently delete files in your source folder" once emptied) — you allow or deny.
- **Rename by modified date:** multi-step prompt: list files → read each file's **modified** date/time → rename to a `YYYY-MMM-DD HH-MM-SS` format → create one folder per date → move each renamed file in. Built with the guardrails above; demo: 64 files processed into date folders, duplicate timestamps suffixed `_1/_2`.
- **Google Docs → formatted PDF (lesson 5):** paste the doc's **shareable link** (Share → Copy link) plus: "**Go through this document… clean and format the content professionally, add proper headings and structure, convert the document into the PDF, name this file with created/modified date, save it into the folder named 'final reports' in Google Drive, show the preview before final.**" → ~3–4 minutes, PDF generated page-wise from the Doc, downloadable.
- **Batch invoice generation (course's flagship example, lesson 5):** folder holds an Excel file of invoice data + a company-details text file; the prompt is fully stepwise: read Excel → read company details → design a professional invoice format → generate **one sample** → wait for confirmation → on "proceed", generate every record → **one PDF per invoice, named by invoice number/customer name, saved into an `invoices` folder, no overwriting** → clean professional formatting. Demo: sample invoice (number, dates, place of supply, bank details, GST, grand total), then 10 invoices, one per customer, paid/pending status visible. Course claim: useful when "you don't have any billing software" — a startup/HR/finance framing, not a guarantee.
